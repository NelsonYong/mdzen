# Frontend Design
Implement real, shippable frontend code with a clear and intentional aesthetic point of view.
Treat design direction as a first-class requirement, not decoration.

## Execute in Order

1. Identify context
- Identify purpose, audience, content priorities, and technical constraints.
- Identify whether the task extends an existing design system or creates a new visual language.

2. Commit to one bold direction
- Choose one strong aesthetic direction and execute it consistently.
- Define one memorable "signature move" (layout gesture, typography treatment, interaction moment, or art direction element).

3. Establish the visual system
- Define CSS variables for colors, spacing, radii, shadows, and timing.
- Pair a distinctive display font with a readable body font.
- Define hierarchy and rhythm before adding decorative effects.

4. Implement production-grade UI
- Build semantic, accessible, responsive layouts.
- Add motion intentionally: prioritize one high-impact entrance sequence and meaningful interaction states.
- Keep effects cohesive with the chosen aesthetic direction.

5. Validate quality
- Verify desktop and mobile behavior.
- Verify keyboard navigation, visible focus states, and color contrast.
- Respect reduced-motion preference for non-essential animations.

## Non-Negotiables

- Avoid generic defaults, including repetitive template layouts and overused "AI look" palettes.
- Avoid unintentional typography choices such as default sans stacks when stronger options are available.
- Avoid shallow visual noise that does not support the concept.
- Preserve existing design language when working inside an established product or design system.

## Aesthetic Guidance

- Use asymmetry, overlap, editorial rhythm, dramatic whitespace, or controlled density to create composition intent.
- Build atmosphere with layered backgrounds (meshes, gradients, patterns, textures) instead of flat fills when appropriate.
- Match complexity to direction:
- For maximalist concepts, build richer layering and choreography.
- For minimal concepts, enforce precision, restraint, and spacing discipline.

## Delivery Standard

- Return working code, not mockups.
- Keep code maintainable and readable.
- Prefer small, reusable components for non-trivial UIs.
- Ensure the final result feels intentional, specific, and memorable for the request context.
