# @mdzen/pet

A reading-companion pet for markdown viewers. GIF-driven sprite with autonomous animation, behavior triggers, mischief, drag, an LLM chat agent (LangChain + OpenAI-compatible), file editing via diff-preview safety flow, and a two-axis emotion system (affection / mood) that hides its internals and only renders through behavior.

Designed to be used by mdzen but built as a standalone package — drop it onto any Node `http.Server` and inject the script tag into any HTML.

## Quick start (standalone)

```bash
pnpm --filter @mdzen/pet build
node --experimental-strip-types packages/pet/example/server.ts
# open http://localhost:4000
```

## Usage as a library

```ts
import { createPet } from '@mdzen/pet';

const pet = createPet({
  workspaceRoot: process.cwd(),
  llm: {
    apiKey: process.env.OPENAI_API_KEY,
    baseURL: process.env.OPENAI_BASE_URL,
    model: process.env.OPENAI_MODEL ?? 'gpt-4o-mini',
  },
});

server.on('request', (req, res) => {
  if (pet.matches(req)) return pet.handle(req, res);
  // ... your other handlers
});

// In your HTML template
const html = `<!doctype html><html>...</body>${pet.scriptTag()}</body></html>`;
```

If `apiKey` is omitted, pet enters **silent mode**: animation, drag, mischief still work, but LLM-driven chat / proposed edits / contextual emotion are disabled. Chat panel still opens with a polite "我今天不太想说话呢" placeholder.

## Architecture

Three layers, cleanly separated:

| Layer | Where | Job |
|---|---|---|
| **Life** | `client/sprite.ts`, `loop.ts`, `boundary.ts`, `motion.ts`, `mischief.ts`, `drag.ts`, `peek-dodge.ts` | 9-state FSM, autonomous wandering, follow-cursor / pounce, long-press drag, peek-on-load, dodge-click. **No LLM calls.** |
| **Dialogue** | `client/chat.ts`, `bubble.ts`, `diff-modal.ts`, `triggers/*`, `cooldown.ts`, `lines.ts`, `presets.ts`, `emotion-client.ts` + server `handler.ts`, `sse.ts` | Selection / copy / idle / ceremonial triggers (probability-gated), bubble component (4 variants), chat panel, SSE consumer, diff modal for proposed edits. |
| **Thinking** | `server/agent.ts`, `tools.ts`, `proposals.ts`, `storage.ts`, `emotion.ts`, `emotion-storage.ts`, `contextual.ts` | LangChain `createAgent` with read-only tools (`list_files`, `read_file`, `search`) + safe `propose_edit` (never writes; only emits SSE). Per-workspace persisted chat + emotion. LLM-generated contextual emotion phrase. |

## Emotion system

Two axes, both persisted to `~/.mdzen/workspaces/<sha1-prefix>/pet-state.json`:

- **Affection** 0-100, long-term. Recovers slowly (`+0.2/min`); positive interactions push up; ignored bubbles, dragged-too-many-times push down.
- **Mood** 0-100, short-term. Pulls toward 50 over ~20 minutes; punctual ups and downs.

Affection maps to 5 zones — **adored / friendly / sulky / cold / hiding** — and each zone shapes:

- The system prompt fragment injected into every LLM call (preset phrases such as *"你正在生气，除非用户明显道歉……否则只回'嗯'"*).
- Whether probabilistic triggers fire at all (`cold` and `hiding` mute them).

The numbers are never displayed. **You only ever see the behavior.** This is the MIT *Socially Intelligent Virtual Petz* principle — meters break the illusion of a relationship.

A second-layer **contextual phrase** is generated by a small LLM call after each chat and cached in pet-state. It references the recent message tail and personality, so two days with the same affection produce different "moods of the moment".

## Safety: how editing works

LLM **never writes the disk**. The flow:

1. Agent calls `propose_edit({path, oldText, newText, reason})`.
2. Server validates path + verifies `oldText` is verbatim in the current file. If not, the tool returns an error and the LLM can re-propose.
3. A `proposalId` is registered (10-min TTL) and a `propose-edit` SSE event is dispatched to the originating session.
4. Browser pops a diff modal (left original / right new / reason header).
5. User clicks **应用** → `POST /api/pet/apply-edit { proposalId }`.
6. Server **re-validates** `oldText` (in case the user edited the file in their IDE between propose and apply) and only then atomically writes (`temp + rename`). On race condition: HTTP 422 with a friendly message.
7. `edit-applied` SSE event is dispatched; affection +5.

This guarantees the agent can never alter your files behind your back, even if the LLM hallucinates a path or your tools.json gets reordered.

## Routes

| Path | Method | Use |
|---|---|---|
| `/api/pet/client.js` | GET | The bundled IIFE script |
| `/api/pet/assets/:gif` | GET | Static GIF assets (only the 9 known names) |
| `/api/pet/sse?session=:id` | GET | EventSource channel for token / tool / propose-edit events |
| `/api/pet/chat` | POST | `{sessionId, text}` — kicks off agent run |
| `/api/pet/history?session=:id` | GET | Chat history for that session |
| `/api/pet/apply-edit` | POST | `{proposalId}` — re-validate then write |
| `/api/pet/state` | GET | Current emotion snapshot (numerical, internal — clients use it for zone gating only) |
| `/api/pet/event` | POST | `{event}` — record an interaction event (click, drag-1st, etc.) |

## Config (createPet options)

```ts
interface CreatePetOptions {
  workspaceRoot: string;            // required, root for file ops
  llm?: { apiKey?, baseURL?, model? };
  storage?: { chatDir? };           // default ~/.mdzen
  personality?: Partial<PersonalityConfig>;
  routePrefix?: string;             // default '/api/pet'
  boundary?: Boundary;              // for client; defaults sensible
}
```

## Building

```bash
pnpm --filter @mdzen/pet build           # tsc + esbuild
pnpm --filter @mdzen/pet test            # node:test
pnpm --filter @mdzen/pet typecheck       # tsc --noEmit
```

Server code emits to `dist/` (compiled JS); client code is bundled to `dist/client.js` via esbuild. Both ship under `files`.
